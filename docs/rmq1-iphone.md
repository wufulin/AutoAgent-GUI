# 通过 RMQ1 连接 iPhone

## 当前范围

在「添加设备 → RMQ1 / iPhone」中连接局域网的 GL.iNet Comet Q
（GL-RMQ1），查看持续更新的手机画面，直接点击、按住拖动，或用鼠标滚轮与触控板滚动。

连接后页面与 Android 保持相同的工作区结构：左侧设备列表、中间 AI 助手、
右侧手机画面。配置 iPhone 独立视觉模型后，可执行首版“搜索并进入微信群”技能；未配置时输入入口保持禁用，手动控制继续可用。

手机画面默认隐藏采集黑边，保持手机比例。可在「显示设置」调整宽度或关闭
「隐藏画面黑边」；设置和状态栏位于画面之外。窄窗口下对话区和手机画面上下
排列，可滚动查看。改变显示设置或窗口尺寸时，尚未松开的手势会取消并释放，需重新操作。
后端读取 H.264 视频并向浏览器持续推送最新 JPEG 画面；画面与输入分别使用
WebSocket，拖动或等待输入结果时画面仍继续更新，不再等待 500 毫秒的截图轮询。
本功能不依赖 ADB、WDA 或手机开发者模式。

本版 AI 仅支持下述微信群导航，不支持直接键盘输入、系统导航键、多点触摸、
音频、云中继或自动重连。旧的 ADB 与远程 Android 入口保持兼容。
控制回执仅表示 KVM 传输完成，手机是否实际响应需要观察新画面确认。

## 连接步骤

1. 按照 [GL.iNet 官方设置指南](https://docs.gl-inet.com/kvm/en/user_guide/gl-rmq1/)
   连接 RMQ1 电源、网络和 iPhone。手机须支持 USB-C 视频输出；
   Lightning 机型及不支持视频输出的设备不在本版范围内。
2. 在可信的 RMQ1 控制台先确认能够看到手机画面并操作手机。
   选择匹配的 iPhone 型号、屏幕方向以及混合鼠标输出 `usb_hybrid`
   （也支持绝对鼠标 `usb`），
   在手机开启辅助触控。方向设置必须与实际手机状态一致。
   设置说明见 [官方控制台指南](https://docs.gl-inet.com/kvm/en/user_guide/gl-rmq1/console_guide/)。
3. 确认手机按键已释放，关闭其他正在控制这台 RMQ1 的客户端。启动一个 AutoGLM-GUI 后端，
   在添加设备窗口选择「RMQ1 / iPhone」，输入 RMQ1 的私有 IPv4 地址，
   例如 `192.168.1.100`。支持 HTTPS 默认端口 443，不接受域名、公共地址或 URL。
4. 点击「检查连接和证书」，将显示的 SHA-256 指纹与可信控制台连接的证书
   SHA-256 指纹核对一致后勾选确认。证书更换后必须重新核对。
5. 用户名保留默认 `admin`，输入 RMQ1 管理员密码，点击「连接 iPhone」。只有认证、HID 检查、
   手机几何配置和首张 H.264 解码画面都成功，设备才会加入列表。
6. 选择设备后点击画面；按住拖动时持续发送移动，松开结束手势。
   鼠标滚轮和触控板滚动会转换为短拖动；本路径不向 iPhone 发送原生滚轮指令。
   点击视频黑边会被拒绝。切换窗口、离开页面、画面过期或方向变化时，手势会取消并释放。
   删除设备卡片上的连接即可断开。

解锁、信任、辅助触控和账号认证由使用者完成。浏览器到后端应使用本机连接
或受信任的 HTTPS；后端到 RMQ1 始终使用经证书指纹核对的 TLS。
不要将应用的既有未认证后端暴露到公共网络。

反向代理须转发 `/api/rmq1/preview` 与 `/api/rmq1/control` 的 WebSocket Upgrade。
浏览器来源默认接受同源地址及开发页 `http://localhost:3000`、`http://127.0.0.1:3000`；
使用其他前端地址时，通过 `AUTOGLM_CORS_ORIGINS` 配置完整来源（多个值用逗号分隔）。
该变量覆盖开发来源默认值，同源入口始终可用；Electron 使用后端动态端口的同源页面。

## AI 搜索并进入微信群

1. 在设置的「iPhone 视觉模型」页签启用 iPhone AI，填写支持图片、工具调用及 JSON 回答的 OpenAI 兼容服务、模型、密钥和温度。它独立于 Android 视觉模型；关闭开关并保存可退回手动模式。
2. 「测试 iPhone 视觉能力」仅使用生成的测试图片，不接触手机；测试通过仍需保存设置，不代表真实设备验收通过。
3. 手机停在已解锁主屏幕，微信已登录，系统简体拼音全键盘可用。选择「搜索并进入微信群」，填写精确群名，例如「青城」，执行任务。
4. AI 优先点击可见微信图标，否则下拉系统搜索打开微信；通过屏幕键盘输入拼音，选择候选字并核对最终汉字，在微信群聊分类中检查唯一精确同名结果，进入并验收群标题后立即停止。
5. 也可选择自动路由输入「搜索并进入“青城”群，不发送消息」。首版只识别有限的等价格式；其他任务请使用技能参数入口，不会转入任意 iPhone 自动操作。

联系人同名、倾城/青城山、多个同名群、结果未完整展示、无结果、键盘不支持或认证弹窗均不能判定成功；需人工处理；接管后重新开始任务前请回到主屏幕。输入只允许发生在系统搜索和微信搜索框，不触碰消息输入区或发送按钮，也不滚动读取聊天历史。进入后的群标题需与搜索结果形成连续证据；KVM 回执或模型自述不能替代截图验收。

任务运行时画面继续更新，人工输入由后端设备租约阻止。「停止并接管」会先中止新动作并等待原手势释放；停止请求被接受后仍可能处于结算中，必须等终态。事件连接断开时应刷新恢复任务状态，不把网络错误当作手机已停止。出现未知结果时先核对手机并使用已有恢复入口，不要重复执行。默认 60 步/10 分钟，纠错最多两轮；达到预算会明确停止。

本轮按用户要求暂不执行真机验证。自动化测试与能力探针不代表任何 RMQ1 固件、iOS 或微信版本的真实成功率。

## 凭据、故障与恢复

- 密码不写入配置、设备列表、日志或浏览器存储。认证 cookie 仅在后端内存中；
  断开后清除。后端重启需要重新登录，不自动恢复连接。
- 连接期间保持同一个 `/api/ws` 会话以启动按需视频并维持认证；
  手势复用此通道，空闲时持续检查状态。会话失效即停止控制，不自动重连。
  RMQ1 固件会在会话建立和关闭时清理 HID 状态，因此连接前须确认设备空闲。
  这不能替代异常后的手机状态核对，也不会删除未确认标记。
- 来电或视频中断后，先结束通话并解锁手机，再点击「复位输入并重新连接」。
  画面仍正常但按钮失灵时，也可从「显示设置」找到此入口。它会关闭旧通道，
  复位 RMQ1 的键鼠输入端点，并用本次内存认证重建控制与视频、等待新画面；
  不重放此前的点击、拖动或滚动。有在途操作或未知结果时拒绝复位，须先核对手机。
  登录已过期时，通过设备卡片的「断开 RMQ1 连接」关闭旧会话，再重新添加并登录。
  不需要重启整个应用，也不要删除待确认标记。此入口不会自动修改鼠标模式或手机设置。
- USB 曾断开后，固件可能仍返回正确的混合/绝对鼠标模式，但 HID 在线标志尚未刷新。
  连接时先校验 USB 连接和鼠标配置，再建立控制会话，最多等待 5 秒收到在线 HID 状态，
  然后才启动视频并加入设备列表；不会通过点击或移动来试探。超时、USB 断开、模式变化
  或控制权被占用时连接失败。操作时仍必须在线。错误提示分别说明 USB 未就绪、
  鼠标模式不支持或 HID 未就绪，无需看到 HID 未就绪就反复修改鼠标模式。
- 每次操作携带连接 ID、画面 ID 和唯一操作 ID。画面有效期为 3 秒；
  发送前再次检查 HID、方向、尺寸及时间。旧画面或黑边坐标不发送输入。
  按下至少持续 50 毫秒，单次手势最长 1500 毫秒，超过上限自动结束；
  单连接最多 1000 个操作。移动事件只保留最新坐标，不积压旧轨迹；最终松开不能丢弃。
- 连接绑定首次确认的鼠标输出模式。仅允许在线的绝对定位 `usb` 和 `usb_hybrid`；
  相对、触摸及未知模式仍拒绝，模式中途变化必须重新连接。
  混合模式定位后至少等待 80 毫秒，再复核画面、几何和控制通道才按下，
  避免 iPhone 将远距离点击误判为从旧位置开始的拖动。这是设备适配间隔，
  不能替代手机画面确认。定位后的复核失败保留未知结果标记，不重放输入。
- 同一操作 ID 和相同内容返回原结果，不重发。不同内容复用 ID 会被拒绝。
  操作完成后必须等到新视频帧，才可进行下一次操作。
  输入前明确拒绝与输入后结果未知分别提示；明确拒绝不会要求人工确认已执行的操作。
- 首次输入前，将待确认标记同步写入
  `~/.config/autoglm/devices/rmq1-<地址哈希>.pending`（0600 权限）。
  标记仅含操作 ID，不含密码、截图或证书。正常释放及通道确认后删除。
  所有平台同步标记文件；POSIX 系统额外同步父目录，Windows 使用文件同步。
- 传输中断或进程异常时保留标记；重新登录、重新核对证书也不会清除它。
  在手机上核对操作是否发生并确认鼠标/按键已释放后，点击
  「我已核对手机状态、释放按键，恢复控制」。这不会重放原操作。
  原连接释放失败时，只尝试在原通道发送释放，不建立新通道重复输入。
- 本版要求单后端进程和单个 RMQ1 控制客户端，不能协调其他 GLKVM 应用
  或独立 AutoGLM 后端的控制权。断线或固件不兼容时须重新连接。

## 验证与回退

### 预览与输入时序

预览编码和发送上限为每秒 20 帧，实际帧率受 RMQ1 视频、网络、编码与浏览器绘制影响。
浏览器显示一帧后才确认接收下一帧，后端跳过中间旧帧，避免网络变慢后仍播放过时画面。
这是 JPEG 最新帧推送，尚未使用浏览器直接解码 H.264；不应将上限视为实测帧率或延迟保证。
旧 `/observe` 接口继续按需返回 PNG，旧 `/gesture` 接口仍可执行有界完整手势。

实时输入在按下时开始，移动只发送最新位置，松开时发送最终位置并释放。
滚动复用同一实时控制通道，期间最多一个手势在途，未执行的滚动量有界；
失焦或退出时取消当前手势并丢弃残余量。
快速反向或切换滚动轴时先结束旧方向，等待释放确认和新画面后响应最新滚动，
不必等待旧轨迹执行完；结果未知时停止，不接着执行排队的滚动。
80 毫秒混合鼠标定位等待、状态复核和 50 毫秒最短按压仍保留，不能用网络回执
替代手机已响应的判断。浏览器失联时后端结束原手势；释放失败继续保留未知结果标记。

这些变化去除了原有固定 500 毫秒轮询等待、拖动中冻结画面和松手后固定 400 毫秒重放。
端到端点击/滚动延迟应使用同一手机、固件、网络与测试页面实测，不以代码定时常量推算提升倍数。

自动化覆盖真实 H.264 编解码、认证前证书校验、坐标黑边与旋转、
无效画面拒绝、操作去重、异常释放、恢复标记、设备列表及前端控制流程。
这些测试使用生成的视频和模拟设备，不代表特定 RMQ1 固件、iOS 或手机的物理验收。

实际验收需记录 RMQ1 固件、iPhone 型号和 iOS 版本，并在无敏感内容的测试页面
检查预览、点击位置、纵横向滑动、断网恢复、旧画面拒绝和释放状态。
在完成此验收前，不应宣称已通过真机验证。

回退时先停止操作，核对手机已释放，再断开设备并回退本次版本。
未确认标记应保留到人工核对完成；不要通过删除标记绕过未知结果。
本次未迁移现有 Android 设备或历史数据。
