# 使用技能库

技能把一个可验证目标拆成固定步骤。每步执行后重新截图验收，通过后才进入下一步；全部步骤完成后还会核对最终条件。

## 创建与编辑

在侧栏打开「技能库」。技能按应用分组，支持“全部”、通用技能及应用筛选；应用技能显示应用标识和功能小图标，通用技能显示功能图标。聊天和定时任务使用同一个带分组、图标和版本的技能选择器。

内置技能提供微信导航示例、iPhone 微信群入口，以及 Android 的“大众点评：按城市搜索店铺”，不发送消息。内置定义只读，可以复制后编辑自己的版本。

新建技能时填写名称、ID、总体目标，并定义：

- 所属应用：选择微信、大众点评、其他应用或通用技能。其他应用填写稳定的应用标识和显示名称；应用分类只影响展示，不授予操作权限。
- 功能图标：选择搜索、聊天、资料等；未知应用和图标使用默认图标，图标随前端分发，不请求外部地址。
- 参数：字符串、整数或布尔值，可配置默认值和候选值。在目标或条件中使用 `{{contact_name}}` 引用。
- 前置条件：开始操作前必须能在当前截图中证实的状态；不满足会停止，不会自动跳过。
- 步骤：目标、完成条件、约束、步数预算，以及导航/读取/写入类型。
- 最终完成条件：所有步骤结束后必须仍能从当前页面证实的结果。

例如打开聊天页，应同时核对联系人身份和聊天页面。出现重名时停止并确认身份；仅同名标题不足以证明联系人正确。完成条件越明确，越容易定位未完成的原因。

写入步骤不支持自动续跑。导航或读取步骤可配置最多三次续跑，系统保留已有上下文，后续续跑需要更多完成条件得到证实；未知操作结果、接管或其他终止失败会直接停止。

## 执行

进入设备聊天页面，选择「技能」，选定技能并填写参数后提交。此路径只需要视觉模型；不会调用 Planner。直接执行也只需视觉模型，但必须显式填写完成条件。复杂任务选择规划；自动路径只匹配明确的内置指令，其余进入 Planner。

执行区展示路径、技能版本、步骤、验收结果和统计。token 用量缺失时显示不可用，不用步骤数估算。模型判断通过不等于已完成真机业务验收；稳定运行前应在目标设备上核对真实结果。

## 版本和停用

编辑会追加新版本，已有定时任务继续使用固定版本。禁用技能会阻止其历史版本新开任务；删除后的 ID 不允许重用。更新冲突时刷新目录后再编辑，避免覆盖其他人的修改。

旧 Workflow 页面和接口已删除，旧纯文本文件不会自动变成技能。需要重新建立带完成条件的技能，再[配置定时任务](./schedule-task.md)。

## 大众点评城市搜索

内置 `dianping_search_shops` v1 源自本地 v6 的已测试流程。填写 `city`（例如广州）和 `shop_name`（例如霸王茶姬），依次返回首页、核对城市、输入并核对完整中文、提交搜索并停在商户列表。预算为 40 步、600 秒，仅适用于 Android；需要至少两家可见匹配门店和可确认的目标城市。它不进入店铺详情，也不翻页采集全部门店。

广州＋霸王茶姬、深圳＋古茗有历史真机通过记录；本次内置发布未重新做真机验收，其他组合和布局仍需验证。坐标参考仅可在当前截图布局吻合时使用。登录、验证码、权限、未知弹窗或无法确认的页面必须停止交由用户处理；约束声明不代表模型在所有情况下都能及时识别。

已有本地 `dianping_city_shop_search` v1–v6 原样保留，列表以“自定义”区分；它与新内置 ID 不冲突，既有定时任务不自动改绑。旧 ID 缺少应用或图标字段时，读取时补齐大众点评分类和搜索标识，不因读取而改写文件；显式设置通用分类不会被覆盖。

## 升级与回滚

前后端同步升级。`app` 和 `icon` 是可选展示字段，缺失的旧定义继续可读；未知应用使用默认应用图标，未知功能图标使用通用标识。技能执行仍固定 ID、版本、参数和平台约束，不按应用分组自动改变执行路由。

升级前备份 `~/.config/autoglm/skills.json`。新版本保存技能时会写入展示字段，旧后端的严格 schema 不识别这些字段；回滚前停止任务并确认设备空闲，同时恢复旧前后端及对应的技能配置备份。不要用旧配置覆盖升级后仍需保留的新技能，先另行留存当前文件。
